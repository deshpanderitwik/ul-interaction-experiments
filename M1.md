# Milestone 1 (M1) — the shippable instrument

> Working doc. Scope for the first version of this app as an actual, shippable
> musical instrument (not a sketchbook, not the thesis video). Sibling to
> `THESIS.md`: THESIS is the argument; this is the product cut of it.

## Why M1 is close

We have two generators — a **melody instrument** (Path Explorations) and a
**barebones rhythm instrument** (Drums) — and, crucially, the recent
**shared-clock combination**: they lock to one pulse and duck against each other
(sidechain). Two separate generators are a demo; two that lock and interact are
an **instrument**. So M1's spine already exists. **M1 is consolidation, closing
the loop, and polish — not a pile of new mechanics.**

## How to think about scope (the rulers)

1. **Scope to one closed loop, not a feature list.** An instrument ships when a
   complete loop works end-to-end: *make → shape → layer → hear the whole.* M1 is
   the smallest set that closes **one** satisfying loop.
2. **The 1–3 min capture is the ruler.** Can you perform a compelling minute —
   groove in, melody in, develop, resolve — with only what's in scope? If yes,
   M1 is right-sized. If a feature doesn't help that minute, it's out. If the
   minute falls flat, something's missing.
3. **Depth over surface.** Ship **one** deep, coherent instrument, not many
   shallow toys. The sketchbook stays a sketchbook.
4. **OTA-only for M1.** Commit to what ships without a native rebuild, so we
   iterate fast to the milestone. Native fidelity is M2.
5. **Draw the line at Thesis Level 3.** Composing/shaping *one living scene* =
   M1. *Linking scenes into an arc / arrangement without a timeline* = the
   research frontier = M2+. That one line settles most scope arguments.

## The M1 promise (one line)

> Open the app and, with your hands, lay a groove and a melodic line that lock to
> the same pulse, shape them live, and play a coherent 1–3 minute piece you can
> screen-record.

Everything below flows from this promise.

## In scope

- **Melody instrument** — Path Explorations, consolidated as *the* melody voice:
  position = pitch, x = velocity, paths / waypoints / dynamic nodes,
  quantize-to-grid. (Already deep; needs cleanup, not new mechanics.)
- **Rhythm instrument** — one canonical drum UI (proposed: the **Kit**).
- **The instrument = the two combined on one clock** — the bottom-nav to move
  between them and the **sidechain pump**. This becomes the app's **front door**,
  not a buried "Combinations" entry.
- **Global musical feel** — tempo + scale/key (already in settings).
- **Coupling visuals + a clean, capture-ready attract state** (no dev chrome).
- **Live MIDI record** (exists) and screen-record readiness.

## Out of scope (→ M2+)

- **Thesis Level 3** — scene-linking, sections, arrangement, song structure.
- **Cross-session save/load** of a composition (needs native storage).
- **Native audio fidelity** — real noise, real sidechain, per-voice pan. M1 ships
  on the OTA approximations.
- **Arbitrary/custom voice combinations** — M1 commits to the *one* strong
  pairing, not a modular rack.
- **The exploratory sketchbook** (fence, tap-color, duet, note-*, adsr, slingshot,
  emitters, …) — not part of the shipped instrument.
- **Sharing / cloud / accounts.**

## Open decisions (decide before build; proposed defaults noted)

1. **Persistence** — is M1 a *live performance* instrument (nothing saved; you
   capture by recording) or must it *keep a loop*? Save needs native.
   **Proposed: performance-only; save is M2.**
2. **Canonical rhythm UI** — Kit (kick/snare/hat) as the one beat, folding
   Subdivisions/base in later? **Proposed: Kit is the beat.**
3. **Sketchbook** — do the old experiments ship **hidden** (a "sketches" drawer)
   or get **pulled** from the M1 build? **Proposed: hidden drawer, off the front
   door.**
4. **Front door** — the combination is the app's home screen (vs a menu you pick
   from)? **Proposed: combination is home.**

## Build punch-list (once scope is locked)

- [ ] Make the combination the app's **front door / home**.
- [ ] Pick the **canonical drum** (Kit); fold/hide the others.
- [ ] **Consolidate the melody instrument** (fold the best path behavior in as the
      default; retire redundant variations).
- [ ] **Attract state**: clean launch, hide dev chrome, minimal gesture-legibility
      hints so a new user can find the core gestures.
- [ ] Make **tempo / scale / key** reachable in the instrument.
- [ ] **Capture pass**: a clean record + screen-capture flow, no clutter in frame.
- [ ] **Hide/pull the sketchbook** per the decision above.

## M2 backlog (parked, with a home so nothing gets lost)

- Native audio: real noise generator + filter, real (tail-ducking) sidechain, pan.
- On-device **save/load** of a session/composition.
- **Level 3**: scene-linking / arrangement without a timeline (the frontier).
- Modular voice combinations (build your own scene).
- Sharing / export (audio or project).
