# Milestone 1 (M1) — the shippable instrument (production)

> Seed spec for M1. **This repo stays the sketchbook**; M1 is built in its own
> repo + thread as a leaner, production-focused app. This doc is the source of
> truth for M1 scope/architecture and seeds that new repo.

## What M1 is

**Paths (melody) + Drums (rhythm), realized as fully as possible, and shipped as
a finessed production experience over TestFlight.** Not a sketchbook, not the
thesis video — a real instrument you can hand someone.

The recent shared-clock combination already makes them one instrument (they lock
to a pulse and duck against each other). M1 takes that from "works" to "polished
and deep."

## Decisions (locked)

- **Two instruments only** — Paths + Drums. Nothing else ships.
- **Play-only** — no saving, no recording. You perform it.
- **Full production finesse** — **native builds are in scope** (not OTA-only).
  Ships via **TestFlight**. OTA still used for JS-only iteration on the prod
  channel; native changes rebuild.
- **Go as deep as possible on the Paths↔Drums interaction** (see Depth targets).
- **Separate repo + thread.** This repo remains the sketchbook.

## The M1 promise (one line)

> Lay a groove and a melodic line that lock to one pulse, shape them live, and
> play a finessed 1–3 minute piece — realized as fully as possible and shipped to
> TestFlight.

## Depth targets — "as fully as possible"

### Rhythm → a full drum kit
- Voices: kick, snare, closed/open hi-hat, toms, clap, rim, crash/ride.
- **Native audio:** real **noise generator + filter** for snare/hats/cymbals
  (sweepable — open/closed hat, tune the snare); **pitch envelope** on kick/toms
  for punch; per-hit velocity.
- Grid scaled up: more lanes, finer resolution (e.g. 16 steps), swing/feel.

### Melody → Paths realized
- The full Path Explorations vocabulary (paths, waypoints, dynamic nodes,
  sub-paths, x = velocity, quantize-to-grid), consolidated and cleaned.
- **A proper melodic voice** (native: envelope + filter, maybe 2–3 timbres) —
  graduate from the bare decaying sine.
- Scale / key / octave range.

### Glue → real sidechain
- **Native** kick → melodic-bus ducking: tail-ducking, continuous swell (the real
  effect, not the OTA onset-only approximation). Depth + release dials.

### Master-bus effects → make it pop
- **Native** master chain on the combined signal: EQ, saturation/drive (warmth),
  **bus compression** (glue/loudness), **reverb** (space), **limiter** (loudness
  + safety). This is the single biggest "sounds produced, not like a demo" lever.

### Production finesse
- Clean attract/launch state, minimal gesture-legibility hints, a coherent visual
  design system, 60 fps, mixed levels, gapless audio.

## In / Out

**In:** the two instruments; their combination on one clock; full kit; real
sidechain; master FX; tempo/scale/key; coupling visuals; production polish;
TestFlight delivery.

**Out (→ M2+):** saving/persistence, recording/export, Thesis Level-3 scene-
linking/arrangement, custom/modular voice racks, the sketchbook experiments,
sharing/accounts.

## Architecture — the native audio graph (the heart of M1's depth)

Today `NoteSynth` is one `AVAudioSourceNode` summing sines. M1 graduates to a
real mini signal path:

```
melodic voices ─▶ melody bus ─┐
                              ├─▶ sidechain (kick ducks melody) ─▶ master FX ─▶ out
drum voices    ─▶ drum bus  ──┘                                   (EQ▸drive▸comp▸reverb▸limiter)
```

Native workstream: noise+filter drum voices, pitch envelopes, per-bus routing, a
sidechain envelope on the melody bus driven by the kick, and an `AVAudioUnit` FX
chain (reverb/EQ/distortion) plus a compressor/limiter on the master.

## Repo spin-up

- **Strategy: fork-and-strip this repo.** Keep the crown jewels — `path-
  explorations`, `drums/kit`, the settings/scale/tempo/clock infra, the native
  `note-synth` module, and the Expo/EAS plumbing — then delete the sketchbook
  experiments. Fastest way to preserve the hard-won interaction code. (A fresh app
  is cleaner but risks losing behavior; porting the interaction code is required
  either way.)
- **New identity (do NOT reuse the sketchbook's):** new display name, new bundle
  id, new EAS project, new App Store Connect app record, new channel/runtime. M1
  is a distinct app.
- **One-time setup friction to expect (per this repo's README):** the ASC app
  record must be created once in the web UI, and the *first* iOS build for a
  brand-new bundle id needs an interactive TTY once (to bootstrap the distribution
  cert / provisioning profile). After that, headless `eas build`/`eas submit` work.

## Phased build order

1. **Seed the repo** — fork-strip, new identity; boots straight into the
   Paths+Drums combination.
2. **Native audio graph** — buses + master FX first (instant "pop"), then the real
   sidechain.
3. **Full kit** — noise+filter voices, pitch envelopes, scaled-up kit UI.
4. **Melody voice upgrade** — richer native voice; consolidate Paths.
5. **Production finesse** — attract state, hints, design system, perf, levels.
6. **TestFlight** — build, submit, iterate.

## Parked (M2+)

Save/load, recording/export, Level-3 arrangement, sharing, more instruments.
